## 1. 這一輪要解決什麼

超街區切成斜條（T555）後，窗燈改成在每一條的裁切裡直接把夜圖 `s.night` 畫在樓身上（只限供電建築、夜深 > 0.25），跟樓身一起被夜色壓暗；一般建築的窗燈則推進發光層（`nightSprites`，screen 疊加）。所以整排聯排、合成一棟的超街區夜裡幾乎沒燈。

## 2. 改什麼／不改什麼

**改**

1. 窗燈那一段（T259/T212）不再排除超街區斜條：每一條照一般建築的算法推夜圖、`nightCity`、`pushWindowLife446D` 進發光層，但每一筆都帶那一條的裁切（`clipBlockDiag555`），深度記成那一條自己的深度，讓畫在它之後的建築照 T629 擦掉它。
2. 發光層（`nightCompose629` 和關遮擋時的舊迴圈）支援帶裁切的燈。
3. 斜條裁切裡那張壓暗的夜圖改為不畫（已經進發光層）。
4. 逃生閥 `window.__noSbNight643`＝舊式；自檢 `sbNight643`；版本 v13.48／T643。

**不改**

- 燈的數量與位置：只是讓原本就有的窗燈亮起來，不新增燈（業主 T619 的顧慮）。
- 一般建築、施工中建築的窗燈。
- 決策單實驗碼是「最前面那一條推一整張、不裁切」；正式版改成每條各推自己那一條、帶裁切，避免後段的窗燈穿過站在超街區側前方的高樓（T555 當初切條就是為了這種交疊）。畫面上兩者應相同，以守衛的像素數對照。

## 3. 怎麼算做完（動手前寫下）

1. **自檢 `sbNight643`**（煙霧常駐）：合成一條帶裁切的燈，經 `nightCompose629` 只亮在裁切內、裁切外是 0；關閥門時超街區斜條不推窗燈（呼叫路徑存在）。
2. **像素**（`probe643.js`，種子城住宅近景 z=2、午夜）：發光層裡來自超街區斜條的燈 > 0 筆；畫面亮窗像素（亮度門檻）新版比關閥門多；白天（正午）新舊逐像素相同。
3. **煙霧** 3 連跑綠；GitHub Actions 綠；`fp.js --check` 綠。
4. **樣張**：午夜住宅近景、中景。

## 6. 施工紀錄（如實，含失敗）

- **自檢第一版兩項紅**：① 門檻抄 T629 的 600，但測試燈色 #ffd060 三通道和只有 559，改成 > 500；② 用 `String(draw)` 找呼叫路徑，但 `draw` 後來被 T501／T502 包了兩層，只看得到外殼。改在 T501 包之前先記 `drawPath643`。
- **守衛正午比對誤紅（中景 105、72 位元組）**：紅綠燈相位跟著 `draw()` 次數走（`trafClock`），新舊兩版畫的次數不同，右下角一盞燈 5×7 像素不同；關閥門自己跟自己比也會。正午比對改成關紅綠燈（`__noSignal`）。`probe642.js` 的 ph .20 逐像素比對有同樣的隱患（當時湊巧沒撞到），一併改。
- **決策單的夜窗圖跟遊戲開局的城不一樣**：那組圖是跟 D8、煙同一次拍的，前面的工作先把附近超街區設成施工中（D8）、又往前跑了 160 步（煙），所以圖上很多超街區在施工、城也長大了，A／B 差別只落在少數建築上。業主選的是「窗燈進發光層」這個做法，機制跟正式版相同；守衛與樣張用開局種子城。
- **亮窗像素增加不多**（近景 46→54、中景 346→416）：守衛的「亮窗」門檻很嚴（暖黃、R>200），多數窗燈是 screen 疊上去變亮但沒過門檻；放大對照看得出整排窗亮起來。
- **跟實驗碼不同**：實驗碼只在最前面那一條推一整張、不裁切；正式版每條各推自己那一條、帶裁切、深度記本條，避免後段窗燈穿過站在側前方的高樓。每一幀多推約 500～700 筆帶裁切的燈，實測沒有變慢（原本每條在裁切內畫一張夜圖，現在改在發光層畫）。
