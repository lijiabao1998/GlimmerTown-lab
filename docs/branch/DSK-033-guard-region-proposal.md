# DSK-033｜守門升級提案：用「整段標記區」取代「重疊可逆補丁」

- 日期：2026-11-02
- 背景：DSK-027 §7.9。第三個效能候選（`findSite` 同工具快取，量到 55.7% 重複掃描）失敗在守門機制：`perf-patch054.json` 的逐組字面反演在**重疊編輯**下無法還原 native，`S01 byte-exact` 紅。
- 這一張是**設計卡**，不實作；實作要另一張守門卡，且 **需要業主批准**（它改的是守門檔）。

## 1. 現行機制的限制

`perf-patch054.json` 目前是「一組 from→to 字面補丁」：

- 優點：字面釘死、雙向 SHA-256、逐 byte 可驗。
- 缺點：**補丁之間不能重疊**。一旦第二個補丁寫進第一個補丁的 `to` 字串裡，反演順序再怎麼排都會留下殘餘（實際發生：`aiStep` 與 prune 兩組在反演時找不到）。

## 2. 提案：整段標記區（region pinning）

概念與 LAB 的釘死區塊相同，但用在「修改既有函式」：

```
/* DSK-054 REGION canPlace BEGIN */
<完整的新版函式>
/* DSK-054 REGION canPlace END */
```

- 投影器把 **BEGIN 到 END 之間**（含）整段替換回 `regions.json` 裡的原文，再與 baseline 比對。
- `regions.json` 每筆：`{id, originalText, originalSha256, candidateTextSha256}`。
- 區域**不可嵌套**；每個區域必須落在函式邊界（整個函式換掉，不改函式內部片段）。
- 反演後仍然要求整份 `index.html` 逐 byte 等於 T776 baseline —— 判準沒有放寬。

## 3. 為什麼比可逆補丁好

| | 可逆補丁 | 整段標記區 |
|---|---|---|
| 重疊編輯 | 會壞 | 不適用（區域互斥） |
| 反演正確性 | 依賴補丁順序 | 只依賴標記唯一性 |
| 可讀性 | 要對字串 | 看檔案就知道哪些函式被換掉 |
| 負控制 | 缺／重複／變異 | 缺 BEGIN／重複 BEGIN／區域外變異，各自可斷言 |

## 4. 實作要做的四件事（給下一張守門卡）

1. `single-research052-source.cjs`：新增 `stripPinnedRegions()`（先於既有 block 剝除），並保留現有六組補丁作為歷史相容。
2. `regions.json`：由套用腳本產生（存原文＋雙向 hash）。
3. 負控制：缺 BEGIN、重複 BEGIN、區域被改一個字、區域外被改一個字 —— 四種都必須各自首紅在對應守衛。
4. 用這套機制重做 DSK-027 §7.9 的 findSite 快取候選，並重跑：等價 hash（固定 1000 ticks）、固定工作量、ABBA。
