## 1. 這一輪要解決什麼

- T739 的 36 款新美術在繪製時由 `b.art021` 套上，圖存在 `USE021_CACHE`，不在 `SPR`。
- `fp.js` 呼叫的 `GV.fp536()` 只掃 `SPR`，所以 fp 的 3179 葉不含這 36 款：改壞了，`node fp.js --check` 照樣綠。
- main 上守著它們的只有 smoke 的 `useScales021` 結構自檢：數量、四向、夜光只落在不透明處、硬邊、不裁切、非空。它不比像素。

## 2. 改什麼／不改什麼

- **`fp.js`**：進城後另取 T739 的 144 張標準視角，當成偽家族 `use021` 併進指紋。
  - 144 張＝36 款 × 四向；state `{}`、各款原生 lv、v0。這和 smoke 的 `useScales021` 自檢是同一組。
  - 取法：透過遊戲自己的 `GV.useScales021.selftest()`／`assets()`，用每張圖帶的 `__art021` 認款式與朝向。
  - 日、夜各算 CRC32，演算法和 `fp536` 相同。葉子名 `use021.<款式>.r<朝向>`。
  - 取不到介面、缺任何一款的任何一向、缺夜圖，都直接紅。
- **`fp.json`**：用 `node fp.js --expect=use021` 嚴格增量寫入。
  - 只准多出 `use021` 這一族 144 葉。
  - 其他 165 族、3179 葉、1728 超街區必須零變動，否則不寫。
- **新探針 `probeUse021Fp740.js`**（獨立期望值；不開 Chrome、不跑遊戲）：
  1. 七份來源檔（五份美術、kit、`british-complex-primitives014.js`）的 SHA256，等於 GPT 在 `docs/branch/GPT-022-source-manifest.json` 釘的值。
  2. `index.html` 裡嵌的六份 `data-use021-source` 與檔案逐位元相同。
  3. 在 Node `vm` 用純像素假畫布直接跑五份美術原始碼，作法同 GPT 的 `probeUseScalesKitRebuild021.test.js`。算出 144 張日夜的 CRC32，逐葉比對 `fp.json` 的 `use021`：日、夜、寬、高、不透明像素數。
- **不改**：
  - `index.html`：產品位元組不變，版本仍 v14.41／T739；
  - 任何美術與玩法；
  - `style.json` 的家族內容：`use021` 不進七軸記分；
  - 其他 165 族的判準；
  - CI workflow。

## 9. 沒做的／已知限制

- **main 的 CI 仍不跑 `fp.js`。** 這對全部 3323 葉都一樣，不只這 36 款。要不要在 main 推送時加跑，是業主的決定，本卡沒做。
  - 加跑的代價：每次推 main 多約 1 分鐘（雲端容器的耗時）。另外 GitHub 跑機用映像內建的 `/usr/bin/google-chrome`，版本跟著映像更新；如果哪天光柵化改了，main 會紅、Pages 停部署，要有人登記環境差才能恢復。
- 只指紋標準視角。動態狀態（農場曳引機位置）、季節雪、施工、懸停淡出、夜燈合成都是繪製時另外疊的，不在這 144 葉裡；這些仍只有 T739 在 GPT 分支上的雲端驗收。
- 探針只比「核准來源碼 ↔ `fp.json`」，不看遊戲；遊戲端由 `fp.js` 比。兩者都綠，才代表遊戲畫的就是核准的圖。
- **之後改這 36 款要同時更新四處**，探針才會綠：
  1. 來源檔；
  2. `index.html` 的嵌入；
  3. `GPT-022-source-manifest.json` 的 `sources` 釘值（業主批准的新來源）；
  4. `fp.json`（`--expect=use021`）。
- 沒量 `fp.js` 因此多花多少時間：修前 1 次 74.0 s，修後 4 次 57.7–61.0 s，樣本太少（標準 4.1 要每組 ≥30），不下結論。
- 整族消失不判紅（見第 8 節），T741 處理。
