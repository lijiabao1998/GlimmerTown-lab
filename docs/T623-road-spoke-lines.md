## 1. 這一輪要解決什麼

業主 2026-09-24 用手機看 Pages 樣張「住宅近景・白天」，圈出**街道上有斜的、不知道是什麼的斜線**。中景草地上也有成片的白色長刮痕。

進場探針（暫存腳本，不進版本庫）：

- 主畫布上，這些線屬於 1280×661 的**地面快取**（`draw` 在 60651 行把整張快取貼上主畫布）。
- 改在地面快取的 2D context 上掛鉤、強制重烘一次，查詢點全部落在 `drawRoadHierarchy478` 的兩筆 stroke：
  - 49819 行：三向以上路口的放射短標線，`rgba(244,247,250,.75)`；
  - 49822 行：橋、高架、立交的中線，`rgba(246,248,250,.65)`。
- **根因**：線段終點寫成 `(c[0]+p[0])*.62`、`(c[1]+p[1])*.62`（橋面是 `.92`），也就是把「路口中心」和「路口邊點」兩個**螢幕絕對座標**相加再乘係數。原意是 `c+(p−c)*k`：從路口中心往邊點走 62%。
  - 結果線段長度和路口在畫面上的位置成正比：畫面左上角附近的路口看起來幾乎正常，越往右下越長，而且全部朝「遠離畫面左上角」的方向放射，形成業主看到的斜線和草地白色刮痕。
  - 整份 `index.html` 只有這兩處是這種寫法（grep `(a[i]+b[i])*k` 驗證；其餘命中都是等距公式 `(x+y)*16`）。

## 2. 改什麼／不改什麼

1. 49819、49822 兩處終點改成 `c+(p−c)*k`，抽成純函式 `spokeEnd623(c,p,k)`。逃生閥 `window.__noSpokeFix623` 退回舊公式（逐值相同）。
2. 新增自檢 `spokeSelftest623`，掛進煙霧測試。
3. 新增像素探針 `probe623.js`（手動跑，數「落在草地上的近白色像素」）。
4. 版本 v13.30／T623。

**不改**

- 任何建築精靈 ⇒ `fp.js` 應零變動（標線畫在地面快取，不在 SPR）。

## 3. 怎麼算做完（動手前寫下）

1. **純函式**：`spokeEnd623(c,p,k)` 等於 `c+(p−c)*k`；把 `c`、`p` 一起平移，結果跟著平移（與畫面位置無關）；開閥門時逐值等於舊式 `(c+p)*k`。
2. **繪製守衛**（`spokeSelftest623`，煙霧常駐）：用記錄座標的假 context 直接呼叫 `drawRoadHierarchy478`，路口放在畫面右下遠處（sx=900, sy=500, z=2）：
   - 三向路口與十字路口：修正後每一段線的端點都在這一格的菱形外框內（`sx..sx+64z`、`sy..sy+32z`，容差 2z）。
   - 橋面直路段（tier≥3、`t.bridge`）：同上。
   - **守衛有效**：關閉修正閥時，同樣的呼叫必須抓到出界的線段 ≥1。
3. **像素守衛**（`probe623.js`，種子城、正午）：住宅近景（z=2，看 (12,12)）與中景（z=0.75，看 (36,36)），「近白色且四鄰多數是草地綠」的像素，修正後比修正前少 ≥90%。
4. **煙霧**：雲端 3 連跑綠；GitHub Actions 綠；推上 `main` 後 Pages 自動部署成功（這是 smoke→pages 自動路徑的第一次實測）。
5. **指紋**：`fp.js --check` 與 T622 相同（只有已知的雲端環境差 4 葉）。
6. **樣張**：修前修後的住宅近景、中景各一組，傳給業主。

## 6. 施工紀錄（如實，含失敗）

- **範圍在施工中擴大了一次。** 修完長度公式後放大中景看，斜向道路上還有一道道橫跨路面的淡黃線。追下去是第二個錯：`roadPt478` 把遮罩位元對到菱形**頂點**，直路車道線因此是水平或垂直的，橫跨在斜向路面上。業主截圖圈的「街道上的斜線」，對照位置更像是這一種；草地上的白刮痕則是第一種。兩個一起修。這部分的驗收（自檢的方向斷言、探針 ③）是在改碼之後、跑探針之前補寫的，不算「動手前寫下」。
- **第一版像素量尺是錯的。** 原訂「RGB 皆 ≥225 的近白色」，但標線是 75% 透明的白疊在草地上，混色後約 (212,230,210)，根本量不到（8→5 顆）。第二版改成「淡色像素」，又把人行道邊線、路緣這些本來就淡的像素算進去（413→259，只少 37%）。最後改成**比對新舊兩張圖**：只數新舊不同、而且落在草地上的像素，分成「被移走」與「新冒出」兩類。§3 第 3 條原訂的「少 ≥90%」因此換成 §5 的兩個計數，特此記錄。
- **遊戲主程式包在 IIFE 裡**，外部改不到 `groundDirty`。地面快取鍵不含閥門，所以探針每次切換閥門後，先把鏡頭移開兩格再移回，逼快取重烘。
- 沒做成的：
  1. `drawBridgeRefinement478` 的高架細線與 `drawRailBridgeRefinement478` 也用頂點，本輪沒動。實拍新蓋的橋，橋面方向是對的，高架（種子城 (2..5,25)）也沒看到明顯錯向，留待之後逐項看。
  2. 路面精靈本身的黃色碎線（「≡」形小記號）偏雜，屬於路面精靈的美術，另案。
  3. 雲端沒有可比的 perf 基線；本輪只改線段端點，繪製呼叫數不變。
