# T697 — 多格地標排序改用佔地中線：前面的鄰居不再被地標蓋掉

## 1. 這一輪要解決什麼

物件層用畫家演算法：物件按深度排序，後畫的蓋前畫的。多格建築（`sz≥2`、k9）的深度取佔地**最前角**（T367b：`max(viewDep)`）。

緊貼地標前兩個面、但靠近後角的格子，深度比最前角淺，所以會先畫，接著地標整張精靈蓋上去。明明站在地標前面的建築，看起來反而被地標壓在底下。

種子城 5162026 實測：
- 10 座多格地標有這種鄰居。
- 例：k139 中央車站 5×5（原點 (39,25)，最前角深度 72）。它前面 (39..41,30) 的小樓（深度 69–71），屋頂被車站停車場斜切過去；右前 (44,26)、(44,27) 的紅磚樓（70、71），左半被月台、軌道蓋掉。

## 2. 改什麼／不改什麼

**改**：多格建築的排序深度改成佔地深度的中線 `(min+max)/2`。

方形佔地時，這個深度剛好落在兩層鄰居之間：
- 前面緊貼的格子，深度都 ≥ 中線＋1 → 排在地標之後畫；
- 後面緊貼的格子，深度都 ≤ 中線−1 → 排在地標之前畫；
- 兩個側角的格子深度等於中線，但跟地標在畫面上不重疊。

地標精靈本來就被 T596 裁在自己佔地那幾根柱子裡，排序改了也不會多畫或少畫。

逃生閥：`window.__noCenterDep697`（執行期）＝回最前角。

**不改**：超街區（RCI，T555 切條，另一套）；1×1；精靈、地坪、疊畫本身。
