# T697 — 多格地標排序改用佔地中線：前面的鄰居不再被地標蓋掉

**輪次**：r144
**基線**：`171ed15`（v14.00／T696）
**狀態**：已落地（v14.01）；卡面先單獨提交 `8293a8b`
**來由**：T696 卡第 7 節記下的老限制；業主 2026-09-29「直接全部做完吧」。

## 1. 這一輪要解決什麼

物件層用畫家演算法：物件按深度排序，後畫的蓋前畫的。多格建築（`sz≥2`、k9）的深度取佔地**最前角**（T367b：`max(viewDep)`）。

緊貼地標前兩個面、但靠近後角的格子，深度比最前角淺，所以會先畫，接著地標整張精靈蓋上去。明明站在地標前面的建築，看起來反而被地標壓在底下。

種子城 5162026 實測：
- 10 座多格地標有這種鄰居。
- 例：k139 中央車站 5×5（原點 (39,25)，最前角深度 72）。它前面 (39..41,30) 的小樓（深度 69–71），屋頂被車站停車場斜切過去；右前 (44,26)、(44,27) 的紅磚樓（70、71），左半被月台、軌道蓋掉。

## 2. 改什麼／不改什麼

**改**：多格建築的排序深度改成佔地深度的中線 `(min+max)/2`。

方形佔地時，這個深度剛好落在兩層鄰居之間：
- 前面緊貼的格子，深度都 ≥ 中線＋1 → 排在地標之後畫；
- 後面緊貼的格子，深度都 ≤ 中線−1 → 排在地標之前畫；
- 兩個側角的格子深度等於中線，但跟地標在畫面上不重疊。

地標精靈本來就被 T596 裁在自己佔地那幾根柱子裡，排序改了也不會多畫或少畫。

逃生閥：`window.__noCenterDep697`（執行期）＝回最前角。

**不改**：超街區（RCI，T555 切條，另一套）；1×1；精靈、地坪、疊畫本身。

## 6. 施工紀錄（如實，含失敗）

- **卡面第 3 節第 1 條的格數寫錯了。** 卡上寫「前面緊貼 8 格、後面 8 格」，實際是 n×n 佔地外擴圈 4n+4 格，分成前 2n+1、後 2n+1、側角 2；3×3 是 7／7／2。自檢照實際幾何驗 2×2～5×5。
- **外擴圈判斷跟著改了（卡面第 2 節沒寫到）。**
  - 問題：改中線後，兩個側角格的深度剛好等於中線。T696 的判斷用整數比，側角不算後側、不抽。其中尾碼較小的那一格（rot 0 是 (x+n, y−1)）上若有樹，樹的排序比建築早、先畫，前庭石板接著蓋上去。原本按最前角排序時，側角比它淺，是有抽出的。
  - 做法：對中線排序的建築，改用「這一格自己的排序位置比建築早就抽出」；其他建築與閥門下照 T696 原判斷。T696 的自檢不受影響，因為它用的合成物件不帶 `cd697`。
  - 前側外擴格照舊在建築的時點畫：在所有站在它前面的東西之前，也在建築的落地影之前，影子照樣落在石板上。
- **守衛量法換了兩次。**
  1. 卡上寫「用拆掉這棟做遮罩」，行不通。(44,26) 是工業超街區的一格（跟 (44,27) 同一塊），拆掉後相鄰的樓重新拼街區、整片換圖，遮罩膨脹到 6.8 萬像素，舊版一個像素都對不上。
  2. 改用「拆掉地標」當參照，這棟的欄位內只有 87.7%／89.2% 相同。原因是參照本身有干擾：樓的描邊與牆腳縫合照鄰居重畫，旁邊沒有車站時多一道外框；停車場那盞燈的光暈也一起消失。
  3. 最後加守衛鉤子 `__depFirst697`，讓 (39,25) 這座排到最前面先畫，就是「前面的東西都在它上面」的樣子，世界不動：100%／99.7%。
  - 卡上「新版 ≥95% 等於這棟在最上層的樣子」的門檻沒變。量的範圍從「這棟的遮罩」改成「這棟在畫面上的欄位」，因為遮罩做不出來。
- **差異腳本第一版卡住兩次（沒有逾時、renderer 空轉）。**
  - 起初以為是 workflow 的 Chrome 搶 CPU，不是。z=1 全城一次 draw 新版 183 ms、舊版 197 ms。
  - 真正原因：三張整張 PNG（約 4.4 MB）放在同一次 evaluate 回傳。拆成每張一次回傳就正常。
- **殺背景程序時誤殺自己的 shell。** 用 `pkill -f "node diff2.js"` 把自己的 shell 也殺了（exit 144），跟 T693 同一個教訓，改用 PID。
- **港區那一處多查了一次。** 那裡是塔吊腳之間的樹換成大樓牆。拆掉 (34,33) 店屋後樹回來：樹在 k165 佔地 (33,33) 上，店屋緊貼 k165 右前，店屋蓋住樹是對的。

## 7. 沒做的

- **非方形佔地。** 中線的論證只對方形成立；目前多格建築都是 sz×sz（k9 沒有 sz 當 2×2）。以後出長方形地標要重看。
- **兩座多格建築靠近時的前後。** 等大方形用中線排序是對的；大小不同的只在種子城看過實例（港區兩座隔 2 格），沒有一般性證明。
- **側角格上的精靈寬過一格時。** 它跟地標誰先畫取決於尾碼，本來也是這樣，沒處理。
- **效能沒量。** 每棟多格建築多取一次最小值，量級可忽略。
- **前側外擴格的圍欄／綠籬沒抽出。** 仍在建築時點畫；它只跟站在它前面的東西重疊，畫面上後面的樓碰不到它。
