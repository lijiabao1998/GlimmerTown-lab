## 1. 驗收條件（**動手前寫定**，沿用 T535）

1. 全城的生命大事會**滾動播報**：出生／入學／就業／失業／退休／辭世，至少這六種要出現。
2. 播報要有**日期戳**與**市民姓名**——「在噪音裡認出某個熟面孔」是這個原型存在的理由，
   沒有名字就退化成純噪音。
3. 能有讀者一眼看到的**入口**，且不會打斷正在做的事（沿用 T470A1 的「未讀只亮點」慣例）。
4. 可以只看某一類事件（例如只想看辭世），不然大量出生訊息會淹掉稀有事件。
5. 從事件流**點名字能接回履歷**（原型一與原型二的接縫；否則兩個原型是斷開的）。
6. 不新增存檔欄位、不消耗模擬 R()、有逃生閥。
7. 煙霧測試綠 ＋ 本輪新增斷言全過；紅了就退版換題。

## 5. 施工紀錄（如實，含失敗與自捕）

- **施工本身**：`lifeLog` 多推、指揮中心補丁、篩選、點名字接履歷、未讀金點，一次掛上。煙霧 ④d 9/9 第一次就綠。
- **自捕 1**：自我測試「可只看辭世」第一版用 `html.includes('出生')` 當負向斷言——**篩選鈕自己就寫著「出生」**，整頁 HTML 永遠含這個字。改成數 `feedItem535` 列、對 `</a>　辭世` 做精準匹配。教訓與 T537 的「walk 不認識 NA/NB」同類：**量到的字 ≠ 你以為的那個字**。
- **自捕 2**：`commandRouteAudit485A` 是硬編碼 routes。只 `CMD_TABS457.push` 不包審計，overview 會公開顯示「route 缺失：lifefeed」。探針階段就量到了，所以連審計一起包，沒讓它進綠燈後的「已知醜」。
- **未盡（不美化）**：
  1. 甲組仍 **2/3**：個體跟隨（鏡頭跟著一個人走）還沒做。
  2. 開著事件流分頁時新事件**不會自動刷新列表**（只是不累加未讀）。要看到新的得再點一次篩選或分頁。這是「不打斷」的代價，不是漏做的自動捲動。
  3. 無頭證明的是**注入市民**的事件流；真實人口長出來的市民，同一條 `lifeLog` 路徑，但沒在 `pop≥8` 的城市跑過。
  4. T539 留下的「寫入前 clone、讓指紋差回到單一族」本輪沒做——甲優先於乙。
