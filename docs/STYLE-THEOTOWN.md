# STYLE-THEOTOWN — 把 TheoTown 風格變成數字

**用途**：這條線要「對標 TheoTown 的美術規模與風格」。對標必須有數字，否則無法迭代、無法驗收。
**方法**：只讀 TheoTown 的**公開規格文件與官方論壇教學**，抽出可量化的參數，**每條附出處**。
**界線**：只取規格，不取素材。沒有下載、沒有描摹、沒有嵌入任何它的美術檔或截圖片段。
本專案做的是**同一規格等級的原創素材**。

**查不到的寫「未證實」，不猜數字填進去當事實。** 這是本文件的硬規則。

## 1. 幾何與格面

| 參數 | 數值 | 出處 | 對本作的意義 |
|---|---|---|---|
| 一格的顯示像素 | **64×32**（等距視角造成） | TheoTown Wiki「Plugin」條目：*a tile is a square with a side of 8 meters… its display size in pixels is 64×32* | **與本作完全相同**（本作草坪 64×32、2:1 菱形）⇒ 幾何層面本來就是同級，不需要改 |
| 格面實際尺寸 | 8 公尺／邊 | 同上 | 本作未定義公尺，屬敘事層，不影響像素 |
| 精靈的底／腳印慣例 | 插件教學文件多寫「1 格 = **32×32 px**」，3×3 建築 = 288px 畫布 | 多篇印尼文插件教學（Kabar Pangandaran／Gamenosida） | 與上一條**衝突**：官方 wiki 說顯示 64×32、教學說 32×32。合理解讀＝**32×32 是「繪圖時的格面方框」慣例、64×32 是引擎的等距顯示尺寸**。本作採用 64×32 顯示、以 2:1 菱形為格面 ⇒ 兩者一致，無衝突 |
| 等距比例 | **2:1**（寬為高的兩倍，約 26.57°） | 通用等距像素教學（Pixnote、Sprite-AI、SA Pixel Tutorial） | 本作 2:1 ✓ |
| 建築最大高度 | **256 px** | 官方論壇教學「How to create a small building in 10 steps」 | 本作 `bld` 畫布 72×112、英雄建築 400×400（4×4 以上）。**未證實**本作是否觸及等效上限；但本作畫布為固定 72×112 加上繪製高度，實際樓高遠低於 256 ⇒ 無超限風險 |
| 非方形足跡 | 自 **v1.12.26** 起支援 | 官方論壇「Building templates」 | 本作以 `SZB` 支援 2×2～6×6 ⇒ 同級 |
| 畫布寬度不可改、底座必須貼**底邊**（否則 pivot 算錯） | 規則 | 官方論壇「Building templates」 | 本作以 `ax/ay` 錨點（`ay`＝格南角）表達同一件事 ✓ |

## 2. 精靈的幀排列慣例

| 參數 | 規格 | 出處 |
|---|---|---|
| 幀定義語法 | `{"bmp":"x.png","w":…,"h":…,"count":N,"handle x":…,"handle y":…}` | pca.svetikas.lt 文件（改編自官方論壇） |
| 幀數＝橫向排列，`count` 為數量；`handle` 預設**左上角**（建築與道路例外） | 規則 | 同上 |
| 載具預設幀尺寸 | **32×16**（舊系統）；新式 v2 範例 `w:18,h:12,count:4` | 官方論壇「Cars」討論串 |
| 船艦最少幀數 | **4 幀**（雙變體則 8 幀），多格用 `length` 屬性 | pca.svetikas.lt「Ships」 |
| 道路 | `w:32` ＋ `count`，可用 `target w/h` 放大幀 | 官方論壇「Roads」討論串 |
| 水體／閃爍 | `{"bmp":…,"w":32,"handle y":4,"count":32}`，另有 edge frames／sparkle frames／動畫速度 | pca.svetikas.lt「Custom Water」 |
| 幀動畫索引 | `frame animation indices` ＝**陣列之陣列**，索引自 0 起 | pca.svetikas.lt「Frame animation indices」 |
| 本作對照 | 本作載具為 **4 幀**（`A/B × 2`）＋鏡射方向；行人 2 幀 | ⇒ **在規格帶內**（TheoTown 亦為 4 幀制） |

## 3. 夜間層／發光層的定義方式 ★最重要的一條★

TheoTown 的官方做法（**與本作鐵律「先有燈具，才有光」同源**）：

| 規格 | 內容 | 出處 |
|---|---|---|
| 夜光是**獨立的一層**，用**另一張 PNG** 承載 | 「You need a separate PNG with night animations」 | 官方論壇教學「Rotation aware night animations」 |
| 以 `animation` 物件描述 | `"animation"` 內含 `"light": true`、`"light switching": true`、`"frames"` 陣列 | 同上 |
| 旋轉感知建築只能有 **2 或 4 幀**（燈光動畫同） | `"rotation aware": true` 時的限制 | 同上 |
| 燈光與窗戶必須**對齊** | 用 `handle x`／`handle y` 偏移動畫，讓燈光與窗戶重合 | 官方論壇教學「multiple frames + night anims」 |
| 動畫可指定綁定哪一個基礎幀 | `"frame"` 指定（預設 0，第二幀＝1…） | 同上 |
| **很多既有建築沒有燈光**（原話：many buildings lack lights） | 官方論壇夜間教學開場說明 | 同上 ⇒ 即使 TheoTown 本身，夜圖覆蓋也不是 100% |
| 「閃爍」是**開關**語意（light switching）而非連續變化 | 同上 | ⇒ 本作 T537 用固定 alpha 的淡暖光，**語意相容**；連續變化屬加分非必需 |

**推論（本作可直接套用的規格等級）**：
1. 夜層獨立於日層 ✓ 本作已如此（`night` 畫布）
2. 夜光必須與白天畫出的燈具／窗戶**位置重合** ✓ 本作 T537 已遵守
3. 允許「開關式」燈光 ✓
4. **旋轉感知時幀數受限**（2 或 4）⇒ 本作載具 4 幀、行人 2 幀，皆在限制內，**未來新增旋轉變體時不得超過 4 幀**

## 4. 陰影與受光

| 參數 | 數值 | 出處 |
|---|---|---|
| 陰影顏色 | **純黑 20% 不透明度** | 官方論壇教學「How to create a small building in 10 steps」 |
| 陰影長度 | 等於物件高度 | 同上 |
| 陰影必須留在**格面內**（不得溢出腳印） | 規則 | 同上 |
| 受光方向 | **左上**（通用等距慣例：「light usually from upper-left」） | 通用等距像素教學（Pixnote）——**非 TheoTown 官方規格**，標記為業界慣例 |
| 三面明度關係 | 頂面最亮、左面中、右面最暗 | 通用等距教學（Pixnote） |

**本作對照**：T526 打磨層採「每列最左 2px 提亮 14%＋最右 1px 壓暗 12%」＝**左受光**，
與「左上受光」一致 ✓；落地投影用 `rgba(10,14,24,.16)`＝**16%**，TheoTown 為 **20%**
⇒ **本作可再加深一級**（列入可迭代項，非錯誤）。
**T541 更正**：玩家看見的 T516 都會立面在修之前是 `isoBox(..., pal.mid, pal.light)`＝**左暗右亮**，
與官方 Part 1 相反、也與屋頂 `diaEdge(9)` 左亮打架。T541 改為 `pal.light` / `pal.dark`。
夜窗主色改官方 `#FFFBE5`。

## 5. 是否允許半透明邊（抗鋸齒）

| 規格 | 內容 | 出處 |
|---|---|---|
| 關閉抗鋸齒／插值 | 「Disable antialiasing and interpolation/zoom blur」 | 通用等距像素教學（Pixnote） |
| 存成透明 PNG | 規則 | 官方論壇「Building templates」 |
| **TheoTown 官方是否明文禁止 0<alpha<255** | **未證實**——查無官方硬性規定 | — |

**結論（誠實標記）**：**「硬邊」是像素藝術的業界慣例，不是 TheoTown 的官方硬規格。**
本專案仍把它當鐵律（記分卡軸②），因為本作全體走硬邊風格，混入 AA 會不一致。
**但必須註明**：夜光的淡暖光用的是 `rgba(...,.42)`，那是**光**不是**邊**，
TheoTown 的夜層本身就是獨立 PNG、燈光動畫可帶透明度 ⇒ **夜層的半透明不違規**。
記分卡的軸②因此只量**日層**（真正會出現 AA 的地方），夜層另列診斷值。

## 8. 可量化的對標結論（本作 vs TheoTown）

| 面向 | TheoTown | 本作實測 | 判定 |
|---|---|---|---|
| 格面顯示尺寸 | 64×32 | 64×32 | **同級** |
| 等距比例 | 2:1 | 2:1 | **同級** |
| 非方形足跡 | 支援 | 支援（2×2–6×6） | **同級** |
| 載具幀數 | 4 | 4 | **同級** |
| 行人尺寸 | 人≈3px 高 | 3×5 px | **同級** |
| 夜層機制 | 獨立 PNG ＋ 燈光動畫對齊窗戶 | 獨立 `night` 畫布 ＋ 燈光對齊白天像素 | **同級（且本作的做法與其精神一致）** |
| 建築夜圖覆蓋 | 官方承認「很多建築沒有燈」 | **90.1%**（`bld` 511/567） | **本作領先** |
| 整體夜圖覆蓋 | 未證實 | **23.0%**（586/2546 非空日圖） | 未證實 |
| 陰影不透明度 | **20% 黑** | 16% | **差一級 → 可迭代** |
| 建築高度上限 | 256 px | 遠低於 | 同級（無風險） |
| 硬邊 | 業界慣例（非官方規格） | 日層硬邊、夜層允許光暈 | 同級 |
| 單格道具密度 | **未證實** | 未量 | **無法定論** |
| 變體數量級 | **未證實** | `bld` 108 個 RCI 變體（3×3×12） | 無法定論 |

**一句話**：**幾何、幀制、夜層機制三個硬規格本作已在同級；可追的量化缺口是「陰影 16%→20%」與「整體夜圖覆蓋 23%」。**
