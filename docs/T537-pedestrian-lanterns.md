## 2. 驗收條件（動手前寫定）

1. 白天 sprite 上**真的畫出燈具**（不是憑空加光）——遵鐵律「先有燈具，才有光」。
2. 夜圖只亮**白天已經畫了的**像素（燈身本身 ＋ 其相鄰實體像素），不新增任何透明處的光。

5. 不消耗 R()、不動模擬、不進存檔。

## 4. 施工

**Art（`ped` 家族，6 葉子）**——`pedLantern537()` 烘焙後處理：

1. **白天**：在身體外側（`x=round(w*0.72)`, `y=h-3`）畫提把（`#7a5c32`）＋燈身（`#e0a84c`）。
   這是**真實存在的燈具**，不是光暈。
2. **夜圖**：新建同尺寸畫布，燈身填 `#ffeaa6`（最亮），再對**八鄰中白天實體像素**（alpha>40）
   鋪 `rgba(255,214,130,.42)` 的淡暖光。**透明天空一個像素都不加**。

**Wiring**：三個繪製點中的兩處（活動口袋、細節層，兩者都有 `nightDepth` 在 scope）在
`nightDepth>0.25` 時以同樣 transform 合成 `fr.night`。

**新增工具**：`sheet.js`（接觸表）＋ `index.html` 的唯讀出口 `GV.sheet536`。

**不改**：其他 148 族一行未動（指紋差證明）；不動模擬、RNG、存檔。

## 6. 施工紀錄（如實，含失敗與自捕）

- **失敗 1**：`sheet.js` 首版直接在頁面內 `Object.keys(SPR)` ⇒ `ReferenceError: SPR is not defined`。
  根因：整份 script 包在 IIFE 內，`SPR` 不是全域。修法：新增唯讀出口 `GV.sheet536`（與 `fp536` 同一套 walk）。
  **教訓：這條線的所有量測都必須經過檔內出口，不能假設遊戲內部符號可見。**
- **自捕 1**：施工前先用 `sheet.js` 抓 before 快照——**如果先改再抓，A/B 就沒有 before 了**。
  這是業主規則②的隱含前提，寫進流程。
- **失敗 2（T536 遺留）**：首兩次 `fp --check` 報 13 片葉子變動，一度以為遊戲烘焙不決定性；
  實際是我的量測環境不固定（載入舊測試槽 ⇒ `day` 不定 ⇒ 季節變體不同）。`fresh:true` 修正後 0/0/0。
- **未盡（照實寫）**：
  1. **第三處繪製點（地面層，低縮放的點狀行人）沒有夜間合成**——那一層沒有 `nightDepth` 在 scope，
     本輪不動它。低縮放時行人只是 2×2 的點，提燈本來也看不見，不影響體感，但**沒做就是沒做**。
  2. **`ped` 只有 3×5 px，提燈是 1 個像素**——視覺收益本質上很小（×12 接觸表看得清，實景要拉近）。
     真正的大面積空白是 `vehTypes`(86) 與 `railStock469`(264)，那才是收益所在。
  3. 夜圖的「相鄰淡暖光」用的是固定 alpha，**沒有隨 `nightDepth` 連續變化**（只有 >0.25 開關）。
     黃昏交界處可能顯得略突兀，留待後續。
