## 1. 這一輪要解決什麼

T665（原 DSK-001）的 `bareOf` 從落葉樹白天圖推導冬天的禿枝版：擦掉樹冠，從樹幹頂 (20, ySplit) 一個點散出 5～7 根主枝，每根 2 個岔。放大看像一截粗樹幹頂著一個細 V（T665、T669 卡面都記在「沒做」）。

## 2. 改什麼／不改什麼

**改**（照決策單上拍的 C 檔，同一段程式、同一組亂數順序）：
- 樹幹往上延伸成主幹，到樹冠高的六成；下半段兩像素寬（右邊用暗階）。
- 8～10 根枝從主幹不同高度長出（由下往上），越上面越短；每根 3 個岔，末端再分兩根細梢。
- 原本樹冠的範圍內（擦樹冠前 alpha>120 的像素、樹幹頂以上、枝沒畫到的地方）加一層半透明的枝色：兩成是 alpha 110 的點，其餘 alpha 48。積雪版只在不透明像素上積雪（沿用 `snow`，霧不積雪）。
- 逃生閥 `window.__noBareTwig674`＝回到 T669 的畫法（建精靈時讀）；`bareOf` 掛到模組層，讓自檢能用開關閥門各建一張比。

**不改**：哪些樹種冬天變禿（13 種）、樹幹顏色（T668）、樹幹頂門檻（T669）、常綠與亞熱帶樹、其他季節、積雪做法。

## 3. 怎麼算做完（動手前寫下）

1. **自檢 `bareTwig674`**（煙霧常駐）：13 種禿枝精靈，新版比關閥門版的枝像素（alpha 255、不在樹幹帶）多；新版有半透明像素（alpha 40～120）、舊版沒有；樹幹帶（ySplit 以下）新舊逐像素相同；關閥門時跟 T669 的精靈逐像素相同。
2. **守衛 `probe674.js`**（冬天、種子城 (62,26) z=3 與 z=1.5 正午）：新舊有差異；夏天同鏡頭新舊逐像素相同。另外一次性核對（暫存腳本，不進版本庫）：新版畫面跟決策單 C 那兩張圖逐像素相同。
3. **煙霧** 3 連跑綠；`fp.js --check --expect=treeWBare,treeWBareSnow`：只有這兩族變；基線只併這兩族。

## 6. 施工紀錄（如實，含失敗）

- **第一次煙霧 3 連紅**，兩項：
  1. 自己的自檢第 1 項原寫「13 種**每一種**新版枝像素都比舊版多」（卡面第 3 節第 1 條），第 15 種是 158 對 174，反而少。那是窄冠樹，新畫法的枝越往上越短，改由細枝霧補。動手前寫的量尺不對，改成「13 種合計比較多」（2,045 對 1,749），並把少的那一種寫進自檢訊息。這是改驗收門檻，照實記。
  2. DSK-001 的自檢「禿枝版不透明像素 ≤ 白天圖 65%」用透明度 >40 當不透明，細枝霧（48、110）被算成樹冠。改成 >120，跟 `bareOf` 判斷「樹身」同一條，註明 T674。
- 守衛第一次跑時樣張存進了倉庫根目錄的 `scratch674/`（沒被 gitignore），發現後搬到暫存區，沒進 commit。
- **七軸分數下降**：細枝霧是半透明、枝色單一，記分卡的受光方向與細節密度兩軸因此下降。這是業主看圖選的樣子，記分卡只當退化警報，照 T665 以來的慣例接受宣告家族下降。
