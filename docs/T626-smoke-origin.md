# T626 — 煙囪冒煙點：預設視角右偏一格、旋轉後煙往側面或往下飄

**輪次**：r73
**基線**：`dfec779`（v13.32／T625）
**狀態**：✅ 綠燈（卡面先單獨提交 `2e41ca9`，驗收條件寫在動手之前；施工中追加的店屋煙源見 §6）

---

## 1. 這一輪要解決什麼

T608／T613 讓工業廠房與冬季民居從街區精靈上真的煙囪冒煙，但兩張卡都寫了「城裡的煙粒沒拍到過」，自檢又是用同一條公式反推（循環驗證）。今天讀碼：

- 精靈畫在 `bx = sxOf(ax,ay) + (32 − s.ax)·z`，`sxOf(x,y) = ox + ((vx−vy)·32 − 32)·z`，所以精靈上的煙囪像素 p 在畫面上的 x 是 `ox + ((ax−ay)·32 − s.ax + p.x)·z`。
- 煙源 `smokeSrc608` 回傳 `wx = (ax−ay)·32 + 32 + (p.x − s.ax)`，煙粒畫在 `ox + wx·z` ⇒ **煙比煙囪往右多 32·z**（z=2 時 64px，整整一格）。y 方向沒有錯。
- 煙粒存在**世界**等距座標，畫的時候經 `isoW2V` 旋轉：煙源的螢幕位移、往上飄（`wy −= dt·14`）和風（`wx +=`）都被一起轉掉。rot 1／3 時煙往側面飄，rot 2 時往下沉。

## 2. 改什麼／不改什麼

**改**

1. 新增 `smokeViewSrc626(x,y,b)`：同一張街區精靈、同一個錨格，直接算煙囪在 **view 等距座標**（畫面座標扣掉 ox、oy、z）的位置，公式與畫精靈的 `sxOf／syOf` 完全一致，四個旋轉都對。
2. T608 這條煙源（工業、冬季民居、冬季英式店屋）改用它，煙粒標記為 view 座標：往上飄就是畫面往上、風就是畫面往右；畫的時候直接 `ox + vx·z`，不再經 `isoW2V`。
3. 旋轉視角時，場上 view 座標的煙粒清掉（最多 3.4 秒的殘影，換角度後重新冒）。
4. 逃生閥 `window.__noSmokeView626` 退回 T608 原本的世界座標煙源與畫法。
5. 自檢 `smokeView626` 掛進煙霧；T608／T613 兩個舊自檢若因為語意改變而失敗，改成對新函式驗，並把「循環驗證」換成對 `sxOf／syOf` 同一條公式的獨立驗證。
6. 版本 v13.33／T626。

**不改**

- 其他煙源（電廠蒸汽、暴亂煙、施工揚塵、舊 72px 圖集的偏移）：它們有同樣的旋轉問題，另案。
- 煙粒的數量上限、顏色、壽命、局部風（T443）的強度。

## 3. 怎麼算做完（動手前寫下）

1. **幾何守衛**（`smokeView626`，煙霧常駐）：挑幾個有煙囪的街區精靈（工業 2 種、冬季住宅 1 種），在 rot 0～3 各算一次：煙源的畫面位置＝同一個煙囪像素用 `bx + p.x·z、by + p.y·z` 算出的畫面位置（誤差 <0.5px）。**關閉閥門時 rot 0 必須差 32·z**（守衛有效），rot 1～3 更大。
2. **往上飄的方向**：view 座標煙粒一秒後在畫面上的位移，y 必須是負的（往上），四個旋轉都一樣。
3. **實拍**（`probe626.js`）：種子城工業區近景（z=2），讓遊戲跑幾秒冒出煙粒後拍照；修正後煙粒從煙囪頂上方冒出。修前修後各一張給業主。
4. **煙霧**：雲端 3 連跑綠；GitHub Actions 綠；Pages 自動部署。
5. **指紋**：`fp.js --check` 與 T625 相同（煙是粒子，不在 SPR 與超街區快取）。

## 6. 施工紀錄（如實，含失敗）

- **T608／T613「城裡的煙粒沒拍到過」的原因找到了。** 探針只呼叫 `metroArtSeedWorld516` 建城、沒有正式開局，`running=false`，主迴圈 `frame()` 第一行就返回，`updSmoke` 從來沒跑。第一版 `probe626.js` 等 5 秒拍照，兩張都是 0 顆煙。改用既有的測試鉤子 `GV.advanceN(dt,n)` 逐幀推進（`speed=0`，模擬不前進、只推動畫層）後，一次冒出一百多顆。
- **煙本來就很淡。** 煙粒是 4–13px 的方塊、透明度從 0.5 往下掉、顏色是淺灰，正午整張圖幾乎看不出來；給業主的圖因此另做裁切放大＋標註版。煙要不要更明顯屬於全局觀感，要出 2～3 檔給業主挑，本卡不動。
- **量尺改過兩次。** 第一版只量畫面內剛冒出的煙，樣本 1–9 顆，rot 3 修正前那一批剛好全在畫面外（0 顆），守衛拿不到樣本；改成全圖的煙粒對全圖的煙囪頂（畫面外的煙粒照樣有繪製呼叫），每個旋轉 18–25 顆，結果穩定。
- **施工中追加：冬季店屋。** 卡面 §2 把「冬季英式店屋」列在這條煙源裡，但讀碼發現 `smokeSrc608` 開頭只收 k1／k3，T613 放寬的 k2 觸發一進來就回 null——店屋炊煙從來沒生效過（T613 卡面自己也寫了「冬季城裡的炊煙沒有親眼截到」）。新煙源收 k2；閥門關閉時照舊不冒，保留原狀可比。自檢多一項驗它。這一項的驗收是改碼之後補的，不算「動手前寫下」。
- **§3 第 2 條（往上飄）怎麼驗的**：自檢驗了舊式在 rot 2 往下；新式的方向由探針量「剛冒出的煙相對煙囪頂的 y 位移」，四個旋轉都是 −1.4px。
- T608／T613 的舊自檢（`smokeSrc608` 相關）照跑照綠，沒有因為語意改變而失敗，所以沒改。
- **沒做成的：**
  1. 其他煙源（電廠蒸汽、暴亂煙、施工與收割揚塵、燒茬煙柱、街道蒸汽、T159 各種粒子）還是世界座標，旋轉後同樣會偏或往下飄，另案。
  2. 煙粒方塊以左上角為錨點，剛冒出時往右下蓋到煙囪帽 2–3px；改成置中會讓所有煙往左上移半個方塊，屬觀感，沒動。
  3. 煙的可見度（大小、透明度、顏色）沒動，要出檔給業主挑。
  4. 旋轉視角時場上的 view 煙粒直接清掉，換角度後最多 3.4 秒才冒滿。
