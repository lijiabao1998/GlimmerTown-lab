# T668 — 冬天禿枝用樹幹本身的顏色

**輪次**：r115
**基線**：`52c51e4`（v13.72／T667）
**狀態**：已落地（v13.73）；卡面先單獨提交 `25ec3b8`
**業主決定**：2026-09-26 決策單第六批「冬天禿枝是黑綠色，比樹幹暗很多」選 **B 枝用樹幹本身的顏色**（決策單上已說明：白樺、鑽天楊這類淺色樹幹會變米白枝）。

---

## 1. 這一輪要解決什麼

T665（原 DSK-001）的禿枝精靈，枝的顏色取「樹幹那一帶最常見的顏色」，多數樹種取到的是描邊的深綠黑，枝比樹幹暗一大截。

## 2. 改什麼／不改什麼

**改**：`bareOf` 取枝色時，只數樹幹帶裡亮度 55～215 的像素（排除描邊黑、排除高光白），取最常見的那一色當枝色；暗面仍是 ×0.7。都沒有就退回原本的取法。逃生閥 `window.__noBareTrunkColor668`（建精靈時讀，改了要重新載入）。

**不改**：枝的形狀、數量、積雪；哪些樹種變禿；常綠與亞熱帶樹。

## 3. 怎麼算做完（動手前寫下）

1. **自檢 `bareColor668`**（煙霧常駐）：13 種禿枝精靈的枝色（樹幹頂以上、非積雪的不透明像素最常見色）＝該樹種白天圖樹幹帶的色（亮度 55～215 最常見）；枝色亮度都 ≥ 55（不再是黑綠）。
2. **像素**（`probe668.js`，冬天 (67,23)、(62,27) z=2 正午）：新舊有差異；畫面上禿枝範圍的深色像素（亮度 <40）新版比舊版少九成以上。另存新舊各兩張。
3. **煙霧** 3 連綠；GitHub Actions 綠；`fp.js --check --expect=treeWBare,treeWBareSnow`，基線只併這 2 族。

## 4. 施工

- `index.html`：`bareOf`（T665 禿枝烘焙）取枝色時另數一份「亮度 55～215」的樹幹帶顏色，用它最常見的那一色；**樹幹帶沒有這種像素（橡樹、灌木等 3 種）就用預設咖啡色 (107,74,47)**，不再退回描邊色。每張禿枝精靈記下用的顏色與來源（`__trunk668`／`__src668`）。閥 `__noBareTrunkColor668`（建精靈時讀）＝原取法。自檢 `bareColorSelftest668`（掛 `GV`）；v13.73／T668。
- `smoke.js`：自檢清單加 `bareColor668`。
- 新增 `probe668.js`（開兩次遊戲：一次開機前設閥門）。
- `fp.json`、`style.json`：只併 `treeWBare`／`treeWBareSnow` 兩族（變更 22 葉）。

## 6. 施工紀錄（如實，含失敗）

- **自檢第一版紅了兩次**：①照卡面「亮度 55～215」取不到的樹種（橡樹、灌木）原本退回舊取法、又拿到描邊色，橡樹枝還是黑綠——改成取不到就用預設咖啡色；②自檢拿現在的白天圖重算「應該是什麼色」對不上白樺——白天的樹精靈在禿枝烘焙之後又被別的程序改過，重算不可靠；改成禿枝烘焙時把用的顏色記在精靈上，自檢比「畫出來的枝色＝記下的色」。
- **卡面驗收①改寫**：原寫「枝色＝該樹種白天圖樹幹帶的色」，改成「照記下的枝色畫、亮度 ≥ 55、不用描邊色」（理由同上）。
- **看到但沒改（另開題）**：橡樹（11）的禿枝版沒有樹幹——T665 的「樹幹頂」偵測從底往上找第一列寬度 >6 的列，橡樹樹幹底那一列加描邊剛好 >6，整棵樹幹連樹冠一起被擦掉，只剩從地面長出來的一叢枝。這是枝的形狀，不在這張（只改顏色）。
- 白樺、鑽天楊等淺色樹幹的樹，枝是米白色（決策單上已說明，業主選 B）。
