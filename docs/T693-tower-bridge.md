# T693 — 夠長的直線水橋自動長成倫敦塔橋（仍是路）

**輪次**：r140
**基線**：`f31b2f1`（v13.96／T692）
**狀態**：已落地（v13.97）；卡面先單獨提交 `bdd52d5`（T693–T695 一次佔號）
**業主決定**：2026-09-29 決策單第十二批 **12-1 選 C、1-2 選 B（7、9 格的橋中央跨用 3 格）、1-3 選 A（每城一座，最長那座）**（`docs/DECISIONS.md`）。

---

## 1. 這一輪要解決什麼

業主要英倫建築「全做」。倫敦塔橋是還沒進遊戲的倫敦地標。決策單三檔：A 不加／B 3×3 水上裝飾地標（不是路，會切斷路網）／C 夠長的路橋自動長成塔橋。業主選 C：玩家照常蓋路過河，橋夠長時換上塔橋的樣子，車照常從塔門下穿過。

## 2. 改什麼／不改什麼

**改**（照決策單原型碼 `scratchpad/b12/bridge/patch12.js` 的 C 檔，`__x12Bridge=2`＋`__x12BridgeCWide=1`；B 地標那一套不進）：
- 觸發：480A 水橋（`t.road&&t.bridge`，不是高架、不是交流道）、直線、5≤L≤9、不是快速路、沒有岔路。
- 每城一座：最長的那座，同長取格索引最小；不記狀態（存檔讀檔選同一座；之後蓋了更長的合格橋，塔會搬過去）。
- 角色：中央開合跨＝中間 1〜2 格；**奇數 L≥7 取 3 格**（業主選 1-2 B）；兩側各 1 格是塔；其餘是側跨。
- 地面層：整座鋼藍（480A 樣式 1）＋格角石色小墩帽（跟塔格共用的格角不疊）、中央開合縫、不畫 480A 小墩、不撒施工桶、塔格與中央跨不發 T359 橋面矮燈與光洗。
- 物件層：塔下石墩、兩座維多利亞哥德式石塔（尖錐、小塔、金頂）、上層兩條藍白步道、側跨懸鏈、兩端岸塔；依深度跟車交錯（車從塔門下穿過）；塔窗夜圖暖黃（T649）、後畫的塔頂尖錐對夜圖擦除。
- 塔橋 8 鄰格的水面不放礁石／淺灘／浮標。
- 精靈依 (L, 軸, 寬中跨) 在閒置時預烘（requestIdleCallback，切成小段）。
- 逃生閥（執行期，切完 `GV.testRebake592()`）：`window.__noTowerBridge693`＝回原樣；`window.__noTowerBridgeWide693`＝中央跨回 1 格。

**不改**：路網、車流、市民（仍是路）；其他 480A 橋；B 檔（k193 在遠端已是皇家音樂廳 T682，原型的 k193 地標、殘橋樣式、周邊造景判斷全部不進）。

## 3. 怎麼算做完（動手前寫下）

1. **自檢 `towerBridge693`**（煙霧常駐，世界無關）：產生器存在；暫改格子欄位合成一條 7 格直線水橋（測完還原、清快取）→ 被選中、角色依序 側／塔／中×3／塔／側；同時合成一條 5 格的 → 不選（一城一座取最長）；7 格精靈切塊 >0、每塊夜圖亮像素都落在白天不透明處；真的 `draw(.016)` 一次不擲錯；閥門 `__noTowerBridge693` 下推 0 個物件；寬閥門下中央跨 1 格。
2. **守衛 `probe693.js`**：種子城 x=40、y=41–50 造路（跨南方河帶的 5 格水橋，同原型鏡頭）：預設有 11 個塔橋物件、選中 L=5；閥門下 0 個、同鏡頭非水面像素跟閥門版原檔一致；另造 7 格直線橋確認寬中跨 3 格。
3. **一次性核對**（暫存腳本）：同一份 v13.96 上，新版預設 vs 原型 C（`__x12Bridge=2`、`__x12BridgeCWide=1`）同鏡頭正午、午夜、旋轉 90° **逐像素相同**（水面幀不同時報非水面差）；閥門版 vs 原檔同樣。
4. **煙霧** 3 連跑綠；`fp.js --check` 全綠（不動任何精靈族）。

## 6. 施工紀錄（如實，含失敗）

- 第一次核對：每局用 `forceDraw` 連拍想錯開水面幀，結果：
  - 三幀其實一樣（檔案大小相同）；
  - 跨局水面不同：水面差約 6 萬像素、非水面 141–263 像素，非水面這些是被誤判的波光，不能當證據；
  - 第二次改成每鏡頭 99 次 `forceDraw`，午夜一張約 1.4 秒，原型那局的繪圖程序在 16:58 掛掉、evaluate 卡住，手動結束。
  第三次改成同一局隔 0.6 秒拍三張、扣掉動畫像素再比；這次四局水面剛好同幀，整張 0 差。
- `pkill -f "node parity.js"` 比對到自己那個 shell 的指令列，把 shell 一起殺了（沒有影響檔案）；改用 PID 結束。
- 煙霧跑的是隨機生成的城市，自檢不能靠固定座標，所以改成合成測試橋：暫時收起世界上既有水橋的 `bridge` 旗標（不然既有的更長水橋會被選中），測完全部還原。
- 卡面第 3 節第 1 條寫「合成 7 格」：實作改成 9 格＋5 格。L=9 是上限，另外也收起既有水橋，確保選中的是合成那座；9 格照樣驗得到寬中跨 3 格。「閥門下推 0 個物件」實際量的是「閥門下 draw 根本不呼叫推物件」（`__tb693Pushed` 維持 −1），比推 0 個更嚴。換量法，照實記。
- 卡面第 3 節第 2 條的「閥門下同鏡頭跟原檔一致」沒放進 `probe693.js`（守衛只開一局，沒有原檔可比），改由一次性核對做（閥門版 vs 原檔 6 鏡頭 0 差，見第 5 節）。
