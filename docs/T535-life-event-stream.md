## 1. 驗收條件（**動手前寫定**）

1. 全城的生命大事會**滾動播報**：出生／入學／就業／失業／退休／辭世，至少這六種要出現。
2. 播報要有**日期戳**與**市民姓名**——「在噪音裡認出某個熟面孔」是這個原型存在的理由，
   沒有名字就退化成純噪音。
3. 能有讀者一眼看到的**入口**，且不會打斷正在做的事（沿用 T470A1 的「未讀只亮點」慣例）。
4. 可以只看某一類事件（例如只想看辭世），不然大量出生訊息會淹掉稀有事件。
5. 從事件流**點名字能接回履歷**（原型一與原型二的接縫；否則兩個原型是斷開的）。
6. 不新增存檔欄位、不消耗模擬 R()、有逃生閥。
7. 煙霧測試綠 ＋ 本輪新增斷言全過；紅了就退版換題。

## 2. 進場探針（先量）

| 要量什麼 | 量到什麼（出處） |
|---|---|
| 事件從哪裡來 | T533 的 `lifeLog()` 是**唯一**的生命事件出口 ⇒ 只需在該處多推一筆到饋送，六種事件自動全到齊 |
| UI 該掛哪裡 | 有兩個既有資訊中樞：市長辦公室（分頁表 `data-mtab470`，用猴子補丁鏈擴充，6 個先例）、市政指揮中心（`CMD_TABS457` 白名單 ＋ `showCommand457` 的 if 鏈） |
| 可否不動既有函式 | 可以。指揮中心的 `CMD_TABS457` 是 `const` 陣列（可 `push`）、分頁鈕走 `data-cmdtab457`、`cmdBindCommon457()` 統一綁定 ⇒ 用**同款猴子補丁**包一層 `showCommand457` 即可，其餘分頁一行不動 |
| 未讀提示先例 | T470A1：`mayorUpdateHistoryBadge470A1()` ＋ `.hasNew470A1`，非紀錄分頁只亮點不打斷 |
| 語意歸屬 | 生命事件屬於「城市裡的人」，指揮中心的 `citizens` 分頁本來就在講市民 ⇒ 掛這裡語意正確（市長辦公室講的是 AI 決策，放那裡反而怪） |

**結論**：事件資料零成本（`lifeLog` 已經在記），UI 用既有補丁手法掛一個新分頁，
不動任何既有函式本體。這一輪的風險很低，主要工作量在資訊呈現與斷言。

**不改**

- 不動指揮中心既有 6 個分頁的任何程式碼（新增的是補丁後的委派路徑）。
- 不動市長辦公室、不動存檔 schema、不動 RNG。

## 4. 已知取捨（先講清楚）

- **環狀緩衝不進存檔**：重載後饋送清空。理由與 `citizens` 一致——市民本身就是運行時採樣，
  存一份對不上的事件流只會誤導。這個取捨會寫在面板的說明句裡，不讓玩家以為是 bug。
- **上限 120 筆**：夠滾動、又不會讓面板變重。超過就丟最舊的。
- **只在有人的城市才會有內容**：無頭新建城市 `pop=0` ⇒ 空狀態必須寫得清楚（而不是看起來壞掉）。
