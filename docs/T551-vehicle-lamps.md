# T551 — 車輛燈具（把車燈做進素材）

**輪次**：r20　**基線**：`8f07bba` T550 v13.03　**狀態**：✅ 三件成立，已 commit
**選題**：`vehTypes`（86 葉、74.7%、記分卡列為「零夜圖」；業主定調「夜間車流是夜景最強讀感」）

## 1. 進場探針（本輪最重要的發現）
`SPR.vehTypes.arr` ＝ 8 車種 × `{A,B}` 鏡像 ＝ 86 片畫布，**完全沒有夜圖**。
但追繪製點（23891-23895）發現 **車輛早就有夜燈** —— 那是 `nightSprites.push` 的
**執行期 2×2 光塊**（頭燈暖白／尾燈紅，依方向擺放），不是夜圖畫布。兩個後果：

1. **量測失真**：記分卡與夜圖覆蓋率把 `vehTypes` 記成「零夜圖」——又是「行為在執行期、不在素材」。
2. **違反鐵律**：「先有燈具，才有光」——白天 sprite 上根本沒有燈具，夜間卻憑空長出 2×2 光塊。

## 2. 驗收條件（動手前寫定）
1. 白天先在車頭／車尾畫出**燈具**（頭燈暖白、尾燈紅）。
2. 夜圖只亮燈具像素與相鄰「白天已畫」的實體像素。
3. 繪製點改為**合成夜圖**，取代原本的執行期光塊（不能兩者並存＝雙重光）。
4. 逃生閥 `window.__noVehLamp551`；零 R()、不進存檔、整數像素。
5. 指紋差 == 宣告；棘輪不退步；A/B 日夜各一張；煙霧綠。
6. **夜圖覆蓋率必須上升**。

## 3. 施工
`applyT551VehicleLamps()`（跑在後置重建之後）：逐車種逐面掃不透明邊界框，
取中段列的最左／最右實體像素為尾／頭燈位置（`A` 車頭在右、`B` 為鏡像 ⇒ 車頭在左），
白天畫 1–2px 燈具，另建 `NA`／`NB` 夜圖只亮燈具與四鄰實體像素。
繪製點：`b<.55` 時改合成 `NA`／`NB`，移除原本的 `nightSprites.push` 光塊。

## 4. 施工紀錄
- **沒有失敗**，但有一個必須講清楚的**方法論限制**：逃生閥關掉的是「我的新做法」，
  **不等於舊行為**（舊光塊已被移除）。因此 `--pre=__noVehLamp551` 拿到的「before」
  是「**沒有任何車燈**」，不是「舊的執行期光塊」。**日圖的 before/after 因此是嚴謹的，
  夜圖的 A/B 只能證明「有燈 vs 無燈」，不能證明「比舊光塊好看」。**（要嚴格比就得回上一個 commit 跑，成本高，本輪未做。）
- 車燈位置是**掃描邊界框推得**，不是逐車種手校；8 車種形狀差很多（機車 8×6、卡車 15×9），
  **尚未逐車種目視**。

3. 救護車（`SPR.ambulance`）與服務車的警示燈未處理。
