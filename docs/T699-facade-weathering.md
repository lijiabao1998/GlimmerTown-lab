# T699 — 英美立面街屋加風化（B：照一般街區同濃度，畫在真牆上）

**輪次**：r146
**基線**：`4b112d9`（v14.02／T698）
**狀態**：完成（v14.03）
**業主決定**：2026-09-30 決策單第十二批第 2 版 **12-2 選 B**（「2B好了」；`docs/DECISIONS.md`）。

---

## 1. 這一輪要解決什麼

T606 的貼牆風化（簷下灰線、雨漬、牆腳污垢）把英美立面街區（`f577:` 樣式）整個排除。八種立面街屋因此比旁邊的一般街區新：白灰泥排屋、半獨立屋、紅磚連棟屋、馬廄街屋、大宅、高街旅館、芝加哥樓、布朗石。

## 2. 改什麼／不改什麼

**改**：照決策單原型第十三版 `scratchpad/b12/weather/patch12.js` 的 B 路徑（`__x12Weather=2`、不開煤煙）施工。

- 立面繪製器畫牆身時，登記真正的牆面；門、窗、店面、凸窗都避開。
- 風化照一般街區同一套硬像素筆觸、同濃度，畫在登記到的牆身上。
- 繪製時照正前方會蓋住它的東西修剪，碎點不畫。
- 逃生閥 `window.__noFacadeWx699`（執行期）＝回現況，跟原檔逐像素相同。

**不改**：
- 煤煙（C）、再舊一級（D）、舊牆盒子法、量測／校準旗標：一律不進遊戲。
- 一般街區的風化、精靈本身。

## 3. 怎麼算做完（動手前寫下）

1. **自檢 `facadeWx699`**（煙霧常駐）：
   - 閥門關時，某棟立面街屋的精靈有登記到的牆面，貼牆層真的畫出像素；
   - 閥門開時不畫；
   - 任何像素都不變亮；
   - 真的 `draw(.016)` 一次不擲錯。
   - T606 的 `wallDetailSelftest606` 若有「立面街屋不疊貼牆層」一條，改成在閥門下驗、卡上記明。
2. **一次性核對**（同一份 v14.02、同一局亂數、水面釘同一幀）：
   - 新版（閥門關）對原型 B（`__x12Weather=2`）：決策單的鏡頭逐像素相同，至少近景、中景、z1、兩個 z4 特寫；
   - 閥門版對原檔 v14.02：同鏡頭逐像素相同。
3. **守衛 `probe699.js`**（種子城，全城設 300 歲）：
   - 近景 z2 鏡頭新舊不同的像素 >5,000；
   - 變亮的像素 0；
   - 差異只落在立面街屋的精靈範圍裡：立面街屋的外接框之外 0 像素差。
4. **煙霧** 3 連跑綠；`fp.js --check` 全綠（風化是繪製期疊層，不動精靈）。
5. **效能**：同一局量 z1、z2 每幀時間，新版對閥門版，照實記在卡上。

## 4. 施工

- `index.html`：
  - 核心模組放在 `wallCache606` 之前。程式由 `scratchpad/t699/gen699.js` 從原型 `patch12.js` 第十三版產生 `patch699.js`，再套進遊戲。
    - 識別字 `x12*`→`fw699*`、`faces12`→`faces699`。
    - 開關只剩 `fw699On()`＝`!window.__noFacadeWx699`。
    - 產生器最後做殘留檢查：`__x12`、煤煙、舊牆盒子、`zone577:` 一律 0 處。
  - 登記：`makeBlockSprite547` 烘焙立面精靈時，給繪製器 `ctx.face577` 登記牆面，`fw699FaceDone` 收尾，登記結果掛在精靈上（`faces699`）。
  - 畫：`drawWallDetail606` 遇到 `f577:` 樣式時，在閥門關、且有登記牆面的情況下走 `fw699WxFaces`；其他情況照舊 `return 0`。
  - 快取上限：`WD606` 快取 520→800（閥門關時），因為立面街屋多了一批貼牆層精靈。
  - `wallDetailSelftest606`：
    - 原本的「立面街屋不疊貼牆層」一條改成在閥門 `__noFacadeWx699` 下驗；
    - 順手修了版本檢查：原寫法是字串比較 `GAME_ANCHOR>='T606'`，改成數字比較 `/^T\d{3,}$/` 且 `>=606`。現在錨點是 T6xx，兩種寫法結果相同，寫法改了先記在這裡。
  - 新自檢 `facadeWxSelftest699`（6 項）＋GV 出口；版本 v14.03／T699。
- `smoke.js` 加 `facadeWx699`。
- 新守衛 `probe699.js`。
- `fp.json`、`style.json` 不動。

## 6. 施工紀錄（如實，含失敗）

- **第 3 條驗收的量法換了。** 卡上原寫「立面街屋的外接框之外 0 像素差」，實作時改成「同時關掉 T606 貼牆層（`__noWallDetail606`）時新舊逐像素相同」。
  - 原因：外接框要從精靈座標反推到螢幕，旋轉和超街區拼接下容易框錯；
  - 新量法直接證明「差異全部來自貼牆層、精靈與其他層不動」，比外接框嚴。
  - 貼牆層本身只畫在立面街屋登記到的牆面上，這點由自檢和一次性核對（N＝P）保證。
- **門檻分鏡頭。** 卡上寫「近景 z2 >5,000」，套在 day 鏡頭（12,724）。main 鏡頭立面街屋少，另設 >1,000（4,716）。
- **`wallDetailSelftest606` 的兩處改動**（見第 4 節）：一條驗收條件改到閥門下驗、一條版本檢查改成數字比較。T606 卡沒追記，記在這裡。
- **核對用的三份遊戲**（bP、bN、bO）放在 scratchpad，不進版本庫；`parity.js`、`perf.js`、`st.js`、`gen699.js`、`patch699.js` 同。

## 7. 沒做的／已知限制

- **C（煤煙）、D（再舊一級）的程式都沒進來**，業主選的是 B；原型還在 `scratchpad/b12/weather/patch12.js`，要改檔再從那裡拿。
- **決策單上寫明的 B 限制照舊**：
  - 布朗石、連棟屋的正面窗很密，B 只多一條簷線和少數雨漬，跟 A（現況）很接近；
  - 門、窗、店面、凸窗都避開，不風化；
  - 簷線跨接會壓到窗楣頂那一列、戶界落水管頂那一格（決策單「施工時可以再調」第 ② 條；業主沒寫備註，照原型不改）。
- 第十三版給煤煙用的「准燻區」登記（山牆三角、角樓圓柱、轉角小山牆，`zone577`）跟著 C 一起沒進來。
- 開機後才開、關閥門，已烘好的精靈不會重新登記，要 `GV.block559.cache().clear()`（卡第 2 節已寫）。
- 效能：新版每幀多 11～18%、清快取後第一幀多約一半（見第 5 節），沒做優化。
- 旋轉 90°／180°／270°：新版對原型沒逐像素核對（一次性核對只拍 0°），只驗了新版對閥門版「有差、0 像素變亮、不擲錯」（見第 5 節）。
