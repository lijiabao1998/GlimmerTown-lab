# T631 — 指紋台在雲端永遠是紅的：登記平台環境差、`--check` 跑完全部檢查

**基線**：`e833824`（v13.36／T630）
**狀態**：🚧 施工中（卡面先單獨提交，驗收條件寫在動手之前）

## 1. 這一輪要解決什麼

- `fp.json` 的葉子指紋是業主 Windows 本機烘的。雲端（Linux Chromium）有 4 葉永遠不同：`bld.175_1_0`～`bld.178_1_0`（字型繪製差異）。T617 以來每一輪雲端的 `fp.js --check` 都是紅的，卡面只能寫「只有環境差 4 葉」。
- 更糟的是 `--check` 一看到家族變動就立刻 `exit 1`（fp.js 168 行），後面的**超街區指紋（block559）與七軸棘輪根本沒跑**。T624、T628 都得另外複製整個倉庫到暫存目錄跑 `--expect=bld,block559` 才驗得到。
- 結果：雲端每輪的指紋守衛只剩「人眼確認紅燈裡只有那 4 葉」，真的新變動混在紅燈裡容易看漏。

## 2. 改什麼／不改什麼

**改**（只動 `fp.js` 與 `fp.json` 的一個新欄位）

1. `fp.json` 新增 `envLeaves`：`{ "<平台>": { "<葉子>": {d, n, w, h} } }`，登記「這個平台上這幾葉的正確樣子」。比對時，葉子若與 Windows 基線不同、但**完全等於**本平台的登記值，就算「已登記環境差」，不算變動；家族只有這種差異時也不算觸及。登記值本身變了照樣算真變動。
2. `--check` 不再提早退出：先把葉子差、block559、七軸棘輪全部跑完、全部印出，最後才判定紅綠。
3. 新增 `--record-env=葉子,葉子,…`：把**列出的、目前確實與基線不同的**葉子，登記成本平台的環境差，只改 `envLeaves` 欄位（其餘內容照原本的 Windows 基線寫回，不重錄）。沒列出的、或沒有差異的葉子拒絕登記。
4. 新增 `--pre=<JS>`（測試用）：進城前先執行一段 JS，用來在守衛測試裡故意改壞東西。
5. 雲端登記 `bld.175_1_0`～`bld.178_1_0` 四葉（`linux`）。

**不改**

- Windows 基線的所有葉子與家族指紋、block559 基線、style.json。
- 指紋的算法、`--expect` 的判定規則。
- 遊戲本體（`index.html` 不動、版本號不動）。

## 3. 怎麼算做完（動手前寫下）

1. **雲端綠**：登記後，雲端在 HEAD 跑 `fp.js --check`：綠，訊息寫明「已登記環境差 4 葉」；同時印出 block559「與基線一致」與「棘輪 OK」。
2. **守衛有效（葉子）**：`--check --noleft`（關掉左受光＋夜暈，會動到很多家族）必須紅，並列出被觸及的家族。
3. **守衛有效（block559）**：`--check --pre="window.__noMassOrder624=true"`（T624 閥門，改超街區精靈）必須紅，並寫明 block559 與基線不同。
4. **登記值本身被改也要抓**：在暫存複本把 `envLeaves.linux` 裡一葉的 `d` 改掉，`--check` 必須紅、點名那一葉。
5. **拒絕亂登記**：`--record-env=` 帶一個沒有差異的葉子（例如 `bld.1_1_0`）必須拒絕，`fp.json` 不變。
6. `fp.json` 除了新增的 `envLeaves` 欄位以外逐字不變（`git diff` 只有這一段）。
7. 煙霧 3 連跑綠（`fp.js` 不在煙霧裡，只確認沒碰到共用骨架）。
