# T624 — 建築錯位與交疊：街區精靈的兩個量體前後顛倒

## 1. 這一輪要解決什麼

業主 2026-09-24 手機截圖（Pages 住宅近景）圈出**建築物錯位、建築物交疊**。最醒目的一棟是社宅大樓：牆面半腰有一條帶植栽的斜帶，窗格密得像雜訊。

進場探針（暫存腳本與暫時除錯改動，已還原、不進版本庫）：

- 那條斜帶是街區精靈自己畫進去的（整張 224×197 的建築圖），不是外加的貼牆層。
- 這棟是 `(7,16)` 的 4×2 住宅街區（k1 lv2 v2，原型 terrace）。用逃生閥分別產生同一張精靈：
  - 關掉 T582（`__noParcel582`）：斜帶消失，變成一棟完整的樓。
  - 關掉 T604 的「進深 ≥2 住宅不用整棟立面」（`__noBay604`）：雜訊窗變成英式維多利亞立面。
- **根因一：T582 前後切反了。** T582 把 ≥6 格的大街廓沿進深切成兩棟：主體框在 `box[2..]` 的前半 `[0, 0.46]`，第二量體框在後半 `[0.54, 1]`。但 `subPara568` 的第四個座標越大越靠近畫面前方（S 角），所以「後半」其實在前面。第二量體又是**先畫**的（`massBox568`，71130 行），後畫的主體就疊在它上面：後面那棟看起來浮在前面那棟的半腰，那條斜帶就是後棟的基座。
- **根因二：原型表裡本來就有在主體前方的第二量體，也一律先畫。** courtyard（側翼 `[0,.46,.52,1]`）、courtC、factory、heavy 的第二量體都在主體前方，照樣先畫，主體的牆就蓋到側翼上。
- **雜訊窗**：T604 規定「進深 ≥2 的住宅不用整棟立面，改一戶一尖」，但 terrace 這類平屋頂原型根本畫不出山牆，最後退回舊核心畫法：每 3px 一扇 2×2 的小窗，密到像雜訊。

## 2. 改什麼／不改什麼

**改**

1. 新增純函式 `exInFront624(ex, main)`：兩個框在同一個平行四邊形座標裡，第二量體整個落在主體前方（`ex.v0 ≥ main.v1` 或 `ex.u0 ≥ main.u1`）就回 true。
2. `makeBlockSprite547`：第二量體在主體**後方**時照舊先畫；在**前方**時改成主體畫完再畫（立面繪製器路徑在 `chimVisible613` 之前畫，讓被蓋掉的煙囪照樣濾掉；核心路徑在描邊之前畫）。
3. T582 切分對調：主體（有門窗細節的那棟）改在前半、第二量體在後半。兩棟的高度公式不變，只修位置。
4. T604：平屋頂原型（`ar568.flat`）不再被「一戶一尖」擋掉英式／美式立面，因為平頂本來就畫不出尖。
5. 逃生閥 `window.__noMassOrder624` 一次退回 1～4 全部舊行為。
6. 自檢 `massOrderSelftest624` 掛進煙霧。
7. 版本 v13.31／T624。

**不改**

- 原型表（`ARCHE568`）的框與高度、立面繪製器本身、核心畫法的窗格密度（另案，見 §3 第 6 條）。
- 街區怎麼合併、哪些格子畫不畫（「看不見的建築」另卡處理，等業主挑檔）。

## 3. 怎麼算做完（動手前寫下）

1. **純函式**：`exInFront624` 對已知原型給出正確判斷——courtyard、courtC、factory、heavy 的第二量體在前（true）；podTower 這類全地塊裙樓、slabC、dept 在後或重疊（false）；T582 對調後的後棟在後（false）。
2. **像素守衛（自檢，煙霧常駐）**：產生 4×2 terrace 街區（k1 lv2 v2）：修正後，前棟正面最下緣那一排像素（從 S 角沿 W–S 牆往上 2px）必須是牆色，不是第二量體的窗格；關閉閥門時，同一排要抓到第二量體的像素（守衛有效）。實作時若這個判準不可行，改用「修正後精靈與 `__noParcel582` 單棟精靈的前棟牆底一致」，並在 §6 記錄原因。
3. **畫面守衛**（`probe624.js`，種子城住宅近景、中景）：修正前後新舊差異只出現在有第二量體的街區上（其他街區逐像素相同）。
4. **指紋**：`fp.js --expect=block559` 類的超街區快取指紋會變（本卡就是要改它們）；`bld` 以外的家族零變動。雲端的 4 葉環境差照舊。
5. **煙霧**：雲端 3 連跑綠；GitHub Actions 綠；Pages 自動部署。
6. **樣張**：社宅大樓、工業 2×2、courtyard 三組修前修後傳給業主。窗格密度（雜訊窗）若仍明顯，出 2～3 檔對照圖給業主挑，不在本卡自行決定。
