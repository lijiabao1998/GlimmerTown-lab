**輪次**：接入時按實際順序編
**基線**：`ac8e0e7`（v14.38／T735）
**狀態**：卡面先推，施工中
**業主決定**：2026-10-10「你把你列出來的這些做完，我們再說」（清單第 6 項「上線觀測紅燈」；`docs/DECISIONS.md` 同日一列）。

## 1. 這一輪要解決什麼

`index.html` 第 8、9 行引用 `manifest.json`、`icon.svg`，結尾一段在 HTTPS 下註冊 `./sw.js`。這三個檔在實驗線倉庫的任何分支、任何歷史裡都沒有出現過，Pages 部署也只放 `index.html`，所以官方站每次開都會：
- 收到 3 個 HTTP 404；
- 主控台多出幾筆「抓腳本得到 404」的錯誤。

這是實驗線一開始就決定不補檔造成的（T532 第 32 行：「不新增 PWA 附屬檔……這三個 404 在煙霧測試裡列為已知良性並單獨計數」；T620 第 30 行：「Pages 上只能在瀏覽器玩，不能離線安裝」）。結果是所有「主控台必須乾淨」的嚴格檢查永遠紅：T727–T731 的上線觀測都只因這一項而紅。

## 2. 改什麼／不改什麼

- 拿掉 `<link rel="manifest" href="manifest.json">`。
- 圖示改成 `<link rel="icon" href="data:,">`：不發請求，也擋掉瀏覽器自動抓 `/favicon.ico`。分頁圖示跟現在一樣是空白。
- 不再註冊 `./sw.js`（實驗線沒有這個檔，註冊必失敗）；改成一行註解說明原因。
- 跟 T532、T620「不新增 PWA 附屬檔」的決定一致：仍然不補檔，只是不再去要它們。

**不改**：任何畫面、玩法、存檔；`harness.js` 對這三個 404 的「已知良性」分類照留（舊版本、主線仍用得到）。

## 3. 怎麼算做完（動手前寫下）

1. 煙霧 3 連綠，主控台 0 錯誤，「已知良性 PWA 404」計數從 5 筆變成 0 筆。
2. `node fp.js --check` 零變動（產品像素不變）。
3. `index.html` 裡不再有 `manifest.json`、`icon.svg`、`sw.js` 的請求（只剩註解）。
4. 推上 main 後，官方站用 `curl` 抓首頁，確認新的 head 已經上線。
