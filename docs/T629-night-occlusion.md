# T629 — 夜間燈光穿牆：後面建築的窗燈畫在前面建築上

**輪次**：r76
**基線**：`736ef32`（v13.34／T628）
**狀態**：🚧 施工中（卡面先單獨提交，驗收條件寫在動手之前）

## 1. 這一輪要解決什麼

Pages「住宅近景・夜晚」（種子城 (12,12)，z=2，午夜）裡：

- 兩棟高樓之間的空橋，夜裡變成一大塊淡色方塊，下方高樓立面散落一片淡色小方塊，**不對齊這棟樓自己的窗格**；
- 右邊紅磚旅館的**屋頂**上，夜裡出現一排排亮方塊（白天屋頂只有幾個老虎窗）；
- 一條淡色橫線橫跨旅館上方，白天沒有。

進場探針（暫存腳本；攔 `screen` 疊色階段的繪製，再用圖片身分反查是誰的圖）：

- 橫線那一帶畫的是 k34／k105／k106 摩天樓的夜圖（`SPR.bld.34_1_1.night`、`105_1_1.night`、`106_1_2.night`）——這些樓在旅館**後面**，白天被旅館擋住，夜裡它們的燈帶直接疊在旅館上。
- 空橋那一帶有 13 個 T446D 窗燈小方塊（`rgba(255,224,156,.66)`），加上後面街區精靈的夜圖，同樣穿透到高樓立面上。
- **根因**：夜間燈光（`nightSprites`）是在所有物件畫完、晝夜 `multiply` 壓暗之後，才用 `screen` 一次疊上去的（62280 行），沒有深度、沒有遮擋。單棟建築、摩天樓、多格公共建築的夜圖、T446D 窗燈、招牌、路燈光暈都走這一層，所以後面建築的燈會穿過前面的樓。
- 超街區（T555 分條）例外：它的夜圖在物件層裡、裁切範圍內畫，所以有遮擋；但也因此被晝夜 `multiply` 壓暗（這是另一個問題，見 §2「不改」）。

## 2. 改什麼／不改什麼

**改**

1. 夜光先畫進一張離屏光層（`nightLayer629`，與主畫布同大），最後照原本的時機、用 `screen` 疊上主畫布。
2. 物件層每畫一棟建築（含超街區每一條、T596 地塊裁切、T259 施工切片），就記下一筆「遮擋」：它的圖、位置、同樣的裁切、深度。
3. 每一筆夜光記下深度：物件層裡推的＝推它的那個物件的深度；物件層之前推的路面燈光（`rdecGlow`）＝所在路格的深度；物件層之後推的（天空）＝不被擋。
4. 光層依深度順序處理：遇到遮擋就用它的輪廓 `destination-out` 擦掉光層上已經有的燈（＝它後面的燈），遇到夜光就畫上去。
5. 效能：遮擋只在它的範圍碰得到已經有燈的地方才畫；白天（沒有夜光）完全不做。
6. 逃生閥 `window.__noNightOcc629` 退回原本的單次疊加。
7. 自檢 `nightOcc629` 掛進煙霧。版本 v13.35／T629。

**不改**

- 夜光的顏色、亮度、數量、閃爍規則；夜圖本身（指紋不動）。
- 超街區的夜圖仍在物件層裡畫、會被 `multiply` 壓暗，看起來比單棟建築暗（左邊整排白色聯排夜裡幾乎看不到燈）。要不要把它們也搬進光層、變亮，是全局觀感，另出檔給業主挑。
- 樹、車、其他非建築物件不當遮擋。

## 3. 怎麼算做完（動手前寫下）

1. **自檢**（`nightOcc629`，煙霧常駐）：用兩塊合成的「建築」（後面一塊帶夜光、前面一塊不透明且蓋住它的一部分）呼叫光層合成：修正後被蓋住那一半的光層像素是 0、沒被蓋住那一半照亮；**關閉閥門時被蓋住那一半也亮**（守衛有效）。另驗前面建築自己的燈不會被自己擦掉、天空的燈不被擋。
2. **畫面守衛**（`probe629.js`，種子城住宅近景／近景／中景・夜晚）：
   - **只會變暗，不會變亮**：修正後與修正前逐像素比，沒有任何像素的 RGB 總和變大超過 3（遮擋只會拿掉燈）。
   - **管線等價**：修正後的光層但**不做遮擋**，與修正前逐像素差異 ≤ 1%（只允許重疊燈光的四捨五入差）。
   - 探針 §1 的三個位置（空橋下方、旅館屋頂、橫線）修正後那些亮方塊與橫線消失；修前修後各一張給業主。
3. **效能**：夜晚三個鏡頭各 `forceDraw` 20 次，修正前後的中位數耗時；增加不超過 25%（超過就在 §6 寫明數字並提出取捨）。白天鏡頭耗時不變（±5%）。
4. **煙霧**：雲端 3 連跑綠；GitHub Actions 綠；Pages 自動部署。
5. **指紋**：`fp.js --check` 與 T628 相同（只有環境差 4 葉；夜光是執行期疊加，不在 SPR）。
